# Project documentation

This directory contains durable project knowledge. Keep documents concise and update existing pages instead of creating duplicates.

| Area | Purpose |
| --- | --- |
| [`features/`](features/) | Product behavior, user value, scope, and acceptance criteria |
| [`plans/`](plans/) | Implementation plans, slices, verification, and status |
| [`decisions/`](decisions/) | Durable technical or product decisions and their consequences |
| [`runbooks/`](runbooks/) | Deployment, operations, troubleshooting, and recovery procedures |
| [`reference/`](reference/) | Stable APIs, schemas, configuration, and terminology |

## Writing rules

- Link related feature, plan, decision, runbook, and reference pages.
- Prefer one maintained source of truth over repeated explanations.
- Mark assumptions and unknowns; do not present guesses as facts.
- Update documentation before the pull request is created.
