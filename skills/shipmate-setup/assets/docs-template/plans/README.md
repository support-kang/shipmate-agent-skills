# Plans

Use one file per development task. Include scope, non-goals, assumptions, acceptance criteria, implementation slices, planned commit boundaries, slice review packets recorded with each slice (intent, changed behavior, why, review hotspots, verification, residual uncertainty), shipping (target branch and remote, slice commits, push, and PR creation), stop conditions (protocol defaults plus task-specific developer-intervention cases, or an explicit note when none apply beyond the defaults), verification commands, documentation impact, and final evidence. Do not rewrite recorded packets; the pull request copies them as recorded and prefixes each with its commit SHA.
